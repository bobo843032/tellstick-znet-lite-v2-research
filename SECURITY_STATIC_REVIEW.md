# TellStick ZNet Lite V2 firmware 1.3.2: security review

The primary source is the extracted official 1.3.2 root filesystem. Where stated, a narrow follow-up test used an owned physical gateway. Code locations refer to installed firmware modules; decompiled Python 2.7 bytecode was checked against observed behavior where practical. Private keys, credentials, device-specific identifiers, and raw exploit material are not included.

| Finding | Firmware evidence and trust boundary | Physical follow-up | Assessment |
| --- | --- | --- | --- |
| CherryPy session path traversal CVE-2008-0252 | Firmware contains CherryPy 3.7.0. The active web configuration uses RAM sessions, not file-backed sessions. | Anonymous `session_id` cookie attributes were observed; no file-session path was used. | **NOT APPLICABLE** to the active configuration; version and backend **STATIC CODE VERIFIED** |
| Web/API authentication split | `web.base.Server` requires a logged-in CherryPy session for plugin administration and Lua web routes. `/api/*` applies separate Bearer/JWT validation. | Anonymous plugin routes redirected to login; anonymous API operations returned 401. No authenticated upload or owner account flow was exercised. | Boundary **RUNTIME VERIFIED** for anonymous requests; authenticated behavior **STATIC CODE VERIFIED** / **NOT YET VERIFIED** end to end |
| Unsafe plugin YAML | The installed PyYAML 3.11 path uses `yaml.load` on `manifest.yml` before package GPG verification. | A harmless tagged-object sentinel executed in an isolated root Python process on the device; earlier isolated loader work confirmed parse-before-reject ordering. A full authenticated HTTP request was not tested. | Unsafe loader capability **RUNTIME VERIFIED** within the stated isolation; network exploitability **NOT YET VERIFIED** |
| Empty package list | `Loader.importPlugin` requires the `packages` field but not a nonempty list; package signatures are checked only inside the package loop. | Real on-device importer returned success and loaded a manifest-only plugin with `packages: []`. | **RUNTIME VERIFIED**; no package code executed in that test |
| Manifest name and filesystem destination | `Loader.importPlugin` builds a destination from the unnormalized manifest name and calls `shutil.rmtree` when that destination already exists. Python's ZIP member normalization is a separate mechanism. | A uniquely named, test-owned target outside the plugin directory was created and replaced; it and staging were removed afterward. Existing user directories were not used. | Local loader behavior **RUNTIME VERIFIED**; authenticated HTTP path **NOT YET VERIFIED** |
| Detached plugin signatures and signer trust | The loader verifies listed egg files against the active `plugins.keyring`; the manifest itself is not signed. Web custom-key import returns a disabled result. | A locally signed egg was accepted after its public test key was deliberately added by root. The active keyring remained unchanged during later probes. | Positive signature path and root-added signer **RUNTIME VERIFIED**; unknown-signer negative case **NOT YET VERIFIED** |
| `plugins.keyring~` | Loader code refers only to `plugins.keyring`. | Pre-import backups and a separate GPG reproduction identify `~` as the previous public keyring created on import. | **RUNTIME VERIFIED** backup role; not an active trust store |
| Lua-to-Python access | Lua's `require` wrapper exposes registered callable Python plugin members; this is a privileged automation boundary, not a strict sandbox. | No new physical Lua privilege test in this phase. | **STATIC CODE VERIFIED**; specific abuse path **HYPOTHESIS** until tested |
| Remote-support SSH key | The bundled private key is an outbound Paramiko client key for a server/user supplied by a Telldus Live command; the tunnel forwards to local SSH. | Local Dropbear/root SSH was observed independently. The support key was not used against the gateway or any remote service. | Key role **STATIC CODE VERIFIED**; live support tunnel **NOT YET VERIFIED** |
| Firmware update chain | The updater obtains metadata/image/signature separately, checks length and SHA-1, then requires GPG verification before handing the image to the installer. | No update or flash-write test was performed. Earlier branch tests used mocked GPG outcomes. | Code path **STATIC CODE VERIFIED** / **VERIFIED IN EMULATION ONLY**; physical update behavior **NOT YET VERIFIED** |

The current MQTT test plugin establishes that the signed-package and startup path works on physical hardware. It does not grant a general conclusion about authenticated web uploads, the local-owner prototype, radio commands, or other users' gateways. The temporary sensor observer also demonstrated synthetic callback dispatch inside the production daemon; no natural physical sensor callback or sensor-to-MQTT delivery was observed.

Further testing should keep the same boundaries: use only owned hardware and locally created test artifacts, preserve backups, distinguish synthetic from natural events, and keep secret material outside the repository.
