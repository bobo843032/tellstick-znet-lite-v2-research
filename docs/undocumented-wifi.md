Undocumented Wi-Fi — TellStick ZNet Lite V2

Overview

The Telldus TellStick ZNet Lite V2 is primarily presented as an Ethernet-connected home automation gateway. However, investigation of its stock firmware revealed a functional integrated 2.4 GHz Wi-Fi interface.

The wireless hardware is recognized by the Linux kernel, the appropriate driver is installed, and the interface can operate as a Wi-Fi client.

Functional testing demonstrated successful scanning, WPA2 association, DHCP address assignment, and network communication.

The finding is not simply that the chipset supports Wi-Fi. Wireless connectivity was successfully demonstrated on the examined device.

1. Discovery in the Original Boot Log

The following output is reproduced from the captured serial console log.

[    0.000000] SoC: Atheros AR9330 rev 1

During driver initialization, Linux registers the wireless PHY:

[   11.866083] Loading modules backported from Linux version v4.4-rc5-1913-gc8fdf68
[   11.872121] Backport generated by backports.git backports-20151218-0-g2f58d9d
[   12.154904] ieee80211 phy0: Atheros AR9330 Rev:1 mem=0xb8100000, irq=2

Later in the same boot sequence, the network interfaces are brought up:

[   24.199626] IPv6: ADDRCONF(NETDEV_UP): eth0: link is not ready
[   25.717851] IPv6: ADDRCONF(NETDEV_UP): wlan0: link is not ready

These are authentic kernel messages. They contain no personal identifiers or network credentials.

Interpretation

The messages establish that:

* The kernel recognizes the Atheros AR9330 wireless hardware.
* The Linux wireless subsystem creates phy0.
* The network stack recognizes wlan0.
* Wireless support is present in the installed firmware.

The message link is not ready is a normal network-interface state during initialization. It does not establish that the wireless hardware is defective or disabled.

These boot messages alone do not demonstrate a successful Wi-Fi connection. That was verified separately.

2. Wireless Driver and Platform

The wireless interface is associated with the integrated Atheros wireless MAC.

The installed firmware includes the ath9k driver family and the Linux mac80211 wireless stack.

Filesystem inspection also identified the OpenWrt package metadata:

usr/lib/opkg/info/kmod-ath9k.control

The wireless device is associated with the platform path:

platform/ar933x_wmac

This indicates an integrated platform wireless interface rather than an external USB Wi-Fi adapter.

3. Wireless Configuration

The examined OpenWrt configuration referenced the following radio settings:

config wifi-device 'radio0'
    option type 'mac80211'
    option channel '11'
    option hwmode '11g'
    option path 'platform/ar933x_wmac'
    option htmode 'HT20'
    option disabled '0'

The radio was configured for 2.4 GHz operation with HT20 channel width.

The tested client configuration used station mode and WPA2-PSK authentication.

SSID and credential values are intentionally omitted.

4. Functional Verification

Following discovery of the wireless interface, controlled tests were performed against a researcher-operated access point.

Access Point Scanning

The wireless interface successfully detected nearby 2.4 GHz networks.

This established that the radio was capable of receiving wireless management frames and discovering access points.

WPA2 Association

The device successfully associated with a WPA2-protected access point.

Recorded connection characteristics:

Interface:    wlan0
Frequency:    2462 MHz
Signal:       -56 dBm
TX bitrate:   57.8 Mbit/s
Modulation:   MCS 5

These values are preserved from the earlier experiment. The block is a formatted measurement summary, not a verbatim terminal transcript.

The recorded frequency corresponds to Wi-Fi channel 11 in the 2.4 GHz band.

DHCP and Network Connectivity

After association, the interface obtained an IPv4 address through DHCP.

The interface reached an operational network state, and network communication over Wi-Fi was successfully demonstrated.

The experiment also established that Ethernet and Wi-Fi could operate on the same local network.

No production deployment or long-term stability claim is made from this test.

6. Why Was Wi-Fi Not Advertised?

The exact reason Wi-Fi was not exposed as a supported end-user feature is unknown.

Several explanations are technically plausible.

Platform Reuse

The AR933x platform integrates networking and wireless capabilities. Selecting the SoC for its processing, Ethernet, USB, and OpenWrt ecosystem could also provide Wi-Fi hardware without requiring a separate wireless chipset.

Provisioning and Support

Ethernet avoids the need for wireless credential setup, network discovery, reconnect handling, and customer troubleshooting.

For a home automation gateway intended to remain continuously connected, this may have simplified installation and support.

Product Validation

A functioning wireless interface does not necessarily mean the manufacturer validated it for every supported operating condition.

Wireless range, coexistence, reconnection behavior, antenna performance, and regulatory requirements may influence whether a capability becomes an officially supported product feature.

Radio Coexistence

The gateway also contains RF433 and Z-Wave hardware.

However, there is no direct evidence from this investigation that radio interference was the reason Wi-Fi was not offered as a supported feature.

The successful connection test demonstrates that the wireless interface can operate, but it does not establish comprehensive radio coexistence performance.

None of these explanations should be interpreted as a confirmed statement of Telldus’s design decisions.

Network-specific details have been omitted from the functional test documentation.

No wireless credentials, personal identifiers, MAC addresses, BSSIDs, or private IP addresses are published.

No firmware image or hardware-specific calibration data is included.

Conclusion

The Telldus TellStick ZNet Lite V2 contains an integrated Atheros 2.4 GHz Wi-Fi interface that is recognized by the stock Linux firmware.

The interface was not only detected: it successfully scanned for access points, associated using WPA2, obtained an IP address through DHCP, and carried network traffic.

The tested device therefore has functional Wi-Fi capability beyond its commonly documented Ethernet connectivity.

This finding is limited to the examined hardware and firmware configuration. It does not imply official manufacturer support or guarantee equivalent behavior on every TellStick ZNet Lite V2.
